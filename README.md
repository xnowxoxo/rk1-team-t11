# РК1, трек 11: гистограмма + сортировка подсчётом

Массив из 5·10⁸ целых чисел от 0 до 1023. Нужно построить гистограмму и по ней отсортировать массив.

Команда:
- Шамиль Н. - MPI
- Аюпов И. - OpenMP

## Файлы

```
src/      common.h  seq.c  omp.c  mpi.c
slurm/    omp.sbatch  mpi.sbatch
scripts/  analyze.py
logs/     логи Slurm
plots/    speedup.png  efficiency.png
```

В `common.h` то, что общее для всех версий: генерация массива (одинаковая везде) и проверка результата.

## Проверка

seq считает контрольную сумму отсортированного массива Σ sorted[i]·(i+1) и записывает её в `ref_500000000.txt`. omp и mpi считают такую же сумму и сравнивают с эталоном. Если совпало — `OK`.

Вывод: `version;p;time_s;CHECK`, строки с `#` — дополнительная информация.

## MPI

1. rank 0 раздаёт массив через `MPI_Scatterv`. Каждому по n/p элементов, первые n mod p процессов получают на один больше.
2. Каждый процесс строит свою гистограмму.
3. `MPI_Reduce` складывает гистограммы на rank 0, потом `MPI_Bcast` отдаёт итоговую всем.
4. Каждый процесс по общей гистограмме заполняет свой кусок отсортированного массива (те же позиции, что и в Scatterv).

Время считается от Scatterv до конца сортировки. В строке `#detail` время каждого этапа.

## OpenMP

Два варианта гистограммы, выбираются через `OMP_MODE`: `atomic` (общая гистограмма с atomic) и `local` (своя у каждого потока, потом сложить).

## Как запустить на PARAM BILIM

```bash
# на bilim-master
module load intel/mpi/2021.14
make
mkdir -p logs
sbatch slurm/mpi.sbatch
sbatch slurm/omp.sbatch
squeue -u $USER

# после окончания
python3 scripts/analyze.py
```

Для быстрой проверки на маленьком массиве: `HIST_N=1000000 ./bin/seq` и так же для остальных.

## Узел

Заполнить: `srun -N 1 lscpu`, `gcc --version`, `mpirun --version`.
